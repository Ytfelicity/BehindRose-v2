# Rose in my wake · 2.0.0 预览版

本文按当前源码中的完整工作台介绍操作。已发布的预览包可能仍使用较早的布局或按钮名称；请以下载版本随包提供的说明和发行说明为准，源码更新不会自动改变旧安装包。

## 打开程序

从 [GitHub Releases](https://github.com/Ytfelicity/BehindRose-v2/releases) 下载 Windows x64 分发包：

- 安装版：运行 `BehindRose.NetworkAssistant-win-Setup.exe`，完成后从快捷方式打开程序。
- 便携版：完整解压 `BehindRose.NetworkAssistant-win-Portable.zip`，普通双击 `current/BehindRose.exe`，或使用包内根目录的程序入口。保留整个目录，不要单独移动其中的 EXE。旧版普通便携包的入口可能直接是根目录的 `BehindRose.exe`。

不要以管理员身份打开主界面；只有应用配置和恢复时才会请求授权。分发包已经包含 .NET 运行时和工作台文件，不需要安装 .NET 或 Node.js。

当前 EXE 默认打开完整工作台，整个工作台依赖 Microsoft Edge WebView2 Runtime。如果提示缺少组件或工作台未能启动，请从 [微软官方页面](https://developer.microsoft.com/microsoft-edge/webview2/) 安装运行时后重新打开程序。

如需先体验配置和恢复流程，可在 `BehindRose.exe` 所在目录运行 `BehindRose.exe --demo`。演示模式使用内存中的示例配置和备份，不修改本机配置；关闭后示例备份消失。演示不会自动检测网络，也不提供 IP 质量体检，但手动点击浏览器网络或网站检测仍会发送真实请求。

## 体检和修复

一键配置使用的是作者的默认配置，可以直接套用。如果你已经做过特殊设置，请先自行备份完整配置，再考虑是否使用。程序的自动备份只覆盖本次改动涉及的设置，不代替对特殊配置的完整备份；具体调整范围与注意事项见下文。

1. 左侧进入“一键配置”。程序会读取本地客户端和相关配置，可点击“刷新状态”重新检查；这项本机检查不发起网络采样。支持更新的分发包仍会另行检查 GitHub 更新。
2. 点击页面中的“一键配置”，统一生成 TUN、路由、DNS 接管、Chrome / Edge / Firefox DNS 与关闭 Clash IPv6 的方案，没有独立的 IPv6 按钮。如果配置已经就绪，按钮会显示“检测配置效果”，点击后进入网络检测。
3. 查看实际变更列表。修改 Clash 文件前，先在系统托盘右键 Clash Verge 并退出；程序不会强制关闭客户端或浏览器。
4. 勾选“我已确认本次配置调整”，再点击“确认应用配置”。程序会先备份再应用修改，此时出现 Windows 管理员授权窗口。若切换为另一个管理员账号，操作会被拒绝，避免改错用户。
5. 完成后重新打开 Clash。浏览器策略需要保存工作并重启相关浏览器后检查。文件写入成功不等于全部网络效果已验证。

Clash Verge Rev 配置根据标准目录、YAML 结构与目标字段识别，版本号仅作参考。目录或字段无法识别时会显示具体原因，不生成自动修改方案。便携版客户端无法识别时，可先运行客户端，再点击“刷新状态”；非标准配置目录暂不自动修改。预览确认、备份、管理员授权与退出 Clash 的执行检查保持有效。

启用 TUN 会添加自动路由、严格路由和 DNS 接管。严格路由可能影响某些虚拟机或多网卡场景。保留已有 stack、MTU、路由排除、订阅、节点和规则。YAML 解析保存可能规范化排版与注释；备份保留修改前字节。

一键方案不替换上游 DNS 服务器，保留 hosts、分流、fallback、fake-IP 排除和已有节点解析器。关闭 Clash IPv6 对应 `config.yaml` 顶层 `ipv6: false`；不关闭 Windows 网卡 IPv6，也不单独改写 `dns.ipv6`。显示“已关闭”只代表保存的配置，重新打开 Clash 后核对运行效果。

浏览器策略统一纳入一键方案。Chrome/Edge 关闭独立安全 DNS；Firefox 关闭并锁定该项，两项均满足才显示已配置。发现计算机级的同名策略时停止应用。此版不修改 WebRTC 限制。

## 网络检测

左侧进入“网络检测”。当前工作台在同一页提供 IP 质量、浏览器网络、网站连通性三个分区，顶部链接用于滚动到对应位置；各分区分别点击按钮启动，打开页面不会自动采样。源码开发模式由打开工作台的浏览器采样，EXE 的浏览器网络和网站检测由内置 WebView2 采样。

### 浏览器网络：查看公网 IP、DNS 和 WebRTC

1. 找到“浏览器网络”分区。默认选择公网 IP、DNS 与 WebRTC；如需调整，点击工作台顶部“浏览器检测项”。
2. 点击“检测浏览器网络”。结果会逐步显示，DNS 连续采样可能较久，可随时点击“停止”并保留已取得的结果。
3. 也可单独点击“检测 DNS”或“检测 WebRTC”重测对应项目；需要分享结果时点击“复制报告”。

采样来源与范围：

- 公网 IP：ipify。
- DNS：使用 IPLeak.net 的同会话临时域名协议，最多 300 次连续请求，展示实际解析器与官网累积命中次数；支持停止并保留已有结果。
- WebRTC：复用 MyIP 的 Google、BlackBerry、Twilio、Cloudflare 配置，每源最长五秒、取首个映射候选。
- 地区信息：公网 IP 的国家由随包 DB-IP 国家库在本地匹配；IP 质量体检匹配出口时补充城市和网络归属，未知机构保持未知。DNS 解析器的地区和 ISP 使用 IPLeak 在线归属查询。

### 网站连通性：查看网站能否响应

1. 找到“网络连通性”分区，选择“AI 服务”“默认网站”“常用网站”或“我的网站”分组。
2. 选择“多轮采样 · 10 次取最低”或“单次采样 · 请求总耗时”，点击“检测本组”。每个网站右侧可单独重测，运行中可点击“停止”。
3. 查看网站状态和 HTTPS 耗时；多轮结果中的小柱可查看各次采样。若浏览器网络正在采样，点击“检测本组”会先停止它、保留已有结果，再开始网站检测。

网站默认沿用 MyIP 的每站十次取最低成功值、3.6 秒单次超时与原采样间隔。单站重测始终只测一次。这里的耗时包含 DNS、连接、TLS、代理、跳转与网站处理，不是代理节点 Ping；收到响应也不代表账号登录、地区权限或 AI 功能可用。

### IP 质量：查询所选出口的归属和风险

1. 找到“IP 质量体检”分区，选择检测出口。使用“本机 HTTP 代理”时，选择已识别的 HTTP / 混合端口；未找到时可按客户端显示的端口手动填写。也可选择“本机默认网络”。
2. 点击“开始质量体检”，单次查询最长等待 20 秒；运行中可点击“停止体检”。
3. 查看 IP 归属、风险系数、住宅 / 机房和原生 / 广播标记。需要重试时点击“重新质量体检”，需要原始结果时点击“复制 JSON”。

IP 质量体检使用 IPPure 官方公开接口，需要 WebView2 Runtime，不需要 Docker。端口只用于本次查询；代理连接失败不回退直连，不切换节点或修改代理配置。“本机默认网络”沿用系统现有网络行为，可能因分流与浏览器出口不同，以报告实际返回的 IP 为准。风险分值和类型标记直接采用服务返回结果；IPv6 不计算风险系数，缺失字段保持未知，接口验证失败或超时均不代表纯净或零分。任务和报告保留在本机服务内存，刷新页面可恢复，关闭程序后清除。

### 隐私与结果范围

第三方服务会收到必要请求和来源 IP。检测没有作者服务器代测，不自动上传遥测；详细结果仅保留在当前会话，复制报告由用户主动触发。网站自定义列表保存在本机。检测页面只能使用受限的检测和状态接口，不能调用修复或恢复操作；配置修改需从“一键配置”预览并确认。

部分旧版界面的设置页提供“修复后自动联网复检”。如使用该选项，请先阅读来源说明；它会在修复后重新打开 Clash 时启动采样，客户端或代理尚未就绪时可能失败，需要重试。当前完整工作台请按上面的分区按钮手动检测。

超时、无 IPv6 路由、跨域限制和无 WebRTC 地址均不能解释成“无泄漏”。DNS 解析器与网站出口不同也不足以判定泄漏。结果只代表本次检测所用的浏览器或选定出口；EXE 内置浏览器的结果不能代替外部 Chrome/Firefox 的实测。

## 备份和恢复

1. 左侧进入“恢复记录”，找到对应时间和调整范围的记录，点击“恢复设置”。
2. 核对“恢复范围”，勾选“我已确认本次恢复范围”，点击“恢复原设置”，完成 Windows 管理员授权。
3. 恢复前会为当前状态建立快照。如果本工具修改过的目标后来又被改动，会停止恢复以保留后续配置；不会静默覆盖冲突。

备份路径：`%ProgramData%\BehindRose-NetworkAssistant-v2\当前用户SID\backups`。

单份备份文件的读写总上限统一为 128 MiB，包含修改前后快照及编码开销；写入前先检查最终大小，超限就拒绝写入该记录。配置文件本身的限制不变，已有 v2 备份格式继续兼容。

损坏、过大或无法读取的记录会在列表中单独标记，其他记录仍可查看；异常记录不会被自动删除或忽略。只要存在这类记录，配置修改和恢复都会暂停，可读记录的恢复按钮也会禁用。请保留原文件，先排查异常；目录本身的安全检查失败时，不会继续读取该目录。

“操作中断”或“需要恢复”应优先处理。回滚失败时保留备份目录和操作记录。不要手动改动备份清单或权限。

v1.9 的备份目录保持独立；请用原 v1.9 恢复旧版备份。

## 分发、移除和反馈

支持自动更新的新分发包会在启动后后台检查 GitHub Releases，有新版时弹窗提示，确认后才下载并更新；下载可以取消。检查失败时继续使用当前版本。配置写入和恢复期间暂缓更新。更新功能会向 GitHub 发出普通请求，服务方会收到来源 IP。更新源为 Ytfelicity/BehindRose-v2。源码、开发和普通演示模式不执行自动更新；单独的 --update-test 用于内存配置下验收真实更新。详见 [程序更新](程序更新.md)。

便携版不写安装注册表；删除程序目录即可移除程序本体。若需要撤销修复，请先在程序中恢复；删除程序不会自动撤销网络配置。备份和用户偏好会保留。

“帮助与关于 → 复制摘要”可复制不含订阅、节点、密钥、配置原文、原始错误和 IP 的配置摘要，便于反馈问题。旧界面中的对应入口为“设置与关于 → 预览诊断报告”。网络检测页的详细报告可能包含公网 IP，复制前请自行确认分享范围。

预览版尚未数字签名。请连同第三方许可与验证范围一起分发。

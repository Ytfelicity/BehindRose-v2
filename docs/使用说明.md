# 身后红玫瑰 · 网络助手 2.0.0 预览版

## 打开程序

完整解压便携包，普通双击 `BehindRose.exe`。不要以管理员身份打开主界面。程序已经包含 .NET 运行时；网络检测页还需要 Microsoft Edge WebView2 Runtime。

如果检测页提示组件缺失，请从 [微软官方页面](https://developer.microsoft.com/microsoft-edge/webview2/) 安装运行时。配置、体检和备份功能不依赖检测页成功加载。

如需先体验界面，可用命令 `BehindRose.exe --demo`。演示模式使用内存中的示例数据，不修改本机配置、不发起网络检测；关闭后示例备份消失。

## 体检和修复

1. 打开后自动检查本地客户端和相关配置，不自动联网。
2. 点击“一键配置”，统一生成 TUN、路由、DNS 接管、Chrome / Edge / Firefox DNS 与关闭 Clash IPv6 的方案，没有独立的 IPv6 按钮。
3. 查看实际变更列表。修改 Clash 文件前，先在系统托盘右键 Clash Verge 并退出；程序不会强制关闭客户端或浏览器。
4. 勾选已了解改动，再点击“备份并应用修改”。此时出现 Windows 管理员授权窗口。若切换为另一个管理员账号，操作会被拒绝，避免改错用户。
5. 完成后重新打开 Clash。浏览器策略需要保存工作并重启相关浏览器后检查。文件写入成功不等于全部网络效果已验证。

Clash 配置根据标准目录、YAML 结构与目标字段识别，版本号仅作参考。目录或字段无法识别时会显示具体原因，不生成自动修改方案。便携版无法识别时，可先运行客户端再刷新体检；非标准配置目录暂不自动修改。预览确认、备份、管理员授权与退出 Clash 的执行检查保持有效。

启用 TUN 会添加自动路由、严格路由和 DNS 接管。严格路由可能影响某些虚拟机或多网卡场景。保留已有 stack、MTU、路由排除、订阅、节点和规则。YAML 解析保存可能规范化排版与注释；备份保留修改前字节。

一键方案不替换上游 DNS 服务器，保留 hosts、分流、fallback、fake-IP 排除和已有节点解析器。关闭 Clash IPv6 对应 `config.yaml` 顶层 `ipv6: false`；不关闭 Windows 网卡 IPv6，也不单独改写 `dns.ipv6`。显示“已关闭”只代表保存的配置，重新打开 Clash 后核对运行效果。

浏览器策略统一纳入一键方案。Chrome/Edge 关闭独立安全 DNS；Firefox 关闭并锁定该项，两项均满足才显示已配置。发现计算机级的同名策略时停止应用。此版不修改 WebRTC 限制。

## 网络检测

网页工作台进入“网络检测”，原生 EXE 进入“网络出口检测”，选择项目并点击开始。网页由当前浏览器采样，原生 EXE 由内置 WebView2 采样：

- 公网 IP：ipify。
- DNS：使用 IPLeak.net 的同会话临时域名协议，最多 300 次连续请求，展示实际解析器与官网累积命中次数；支持停止并保留已有结果。
- WebRTC：复用 MyIP 的 Google、BlackBerry、Twilio、Cloudflare 配置，每源最长五秒、取首个映射候选。
- 地区信息：随包 DB-IP 国家库在本地匹配；IP 质量体检匹配出口时补充归属，未知机构保持未知。

IP、DNS 和 WebRTC 先采样，再进行网站连通性检测。IPLeak DNS 连续采样可能较久，可单独停止；网站默认沿用 MyIP 的每站十次取最低成功值、3.6 秒单次超时与原采样间隔。停止后不再启动后续阶段。

第三方服务会收到必要请求和来源 IP。检测没有作者服务器代测，不自动上传遥测；详细结果仅保留在当前会话，复制报告由用户主动触发。网页只能向主界面报告受限的任务状态，不能调用修复或恢复操作。

设置页可以开启“修复后自动联网复检”。开启前请阅读来源说明。修复后重新打开 Clash 才启动这次采样；客户端启动或代理连接尚未就绪时可能检测失败，需要重试。

超时、无 IPv6 路由、跨域限制和无 WebRTC 地址均不能解释成“无泄漏”。DNS 解析器与网站出口不同也不足以判定泄漏。结果只代表当前内置浏览器与这次采样，不能代替外部 Chrome/Firefox 的实测。

## 备份和恢复

备份路径：`%ProgramData%\BehindRose-NetworkAssistant-v2\当前用户SID\backups`。

单份备份文件的读写总上限统一为 128 MiB，包含修改前后快照及编码开销；写入前先检查最终大小，超限就拒绝写入该记录。配置文件本身的限制不变，已有 v2 备份格式继续兼容。

损坏、过大或无法读取的记录会在列表中单独标记，其他记录仍可查看；异常记录不会被自动删除或忽略。只要存在这类记录，配置修改和恢复都会暂停，可读记录的恢复按钮也会禁用。请保留原文件，先排查异常；目录本身的安全检查失败时，不会继续读取该目录。

进入“备份与恢复”，选择对应操作查看范围，再确认恢复。恢复前会为当前状态建立快照。如果本工具修改过的目标后来又被改动，会停止恢复以保留后续配置；不会静默覆盖冲突。

“操作中断”或“需要恢复”应优先处理。回滚失败时保留备份目录和操作记录。不要手动改动备份清单或权限。

v1.9 的备份目录保持独立；请用原 v1.9 恢复旧版备份。

## 分发、移除和反馈

支持自动更新的新分发包会在启动后后台检查 GitHub Releases，有新版时弹窗提示，确认后才下载并更新；下载可以取消。检查失败时继续使用当前版本。配置写入和恢复期间暂缓更新。更新功能会向 GitHub 发出普通请求，服务方会收到来源 IP。更新源为 Ytfelicity/BehindRose-v2。源码、开发和普通演示模式不执行自动更新；单独的 --update-test 用于内存配置下验收真实更新。详见 [程序更新](程序更新.md)。

便携版不写安装注册表；删除程序目录即可移除程序本体。若需要撤销修复，请先在程序中恢复；删除程序不会自动撤销网络配置。备份和用户偏好会保留。

“设置与关于 → 预览诊断报告”可保存不含订阅、节点、密钥、配置原文、原始错误和 IP 的摘要。网络检测页的详细报告可能包含公网 IP，复制前请自行确认分享范围。

预览版尚未数字签名。请连同第三方许可与验证范围一起分发。

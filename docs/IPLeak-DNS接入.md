# IPLeak DNS 接入

DNS 解析来源使用 [IPLeak.net](https://ipleak.net/) 实际服务，保留现有卡片界面。协议依据为官网 `/static/js/index.js?ts=1791555000` 的 `dnsDetection`、`makeID` 与 `ensureIpBox`，2026-10-18 核对，参考文件保存在 `artifacts/ipleak-integration/`。不加载或执行官网脚本。

## 采样与显示

- 每次手动开始生成新的 40 位小写字母、数字会话标识。当前浏览器顺序 GET `https://{session}-{step}.ipleak.net/dnsdetection/`，step 从 1 到 300。完成一次请求后才开始下一次，前 99 次间隔 1 毫秒，第 100 次起间隔 1 秒，第 300 次后结束，与官网一致。失败仍记入已结束请求次数，并按同一节奏继续。
- 响应 `session` 必须与本次会话一致，`ip` 是累积的 IP → 命中次数映射。每个解析器首次出现时创建卡片，此后直接更新官网累积次数，不自行相加、排序或推断 DNSSEC。IP、次数和字段原文保留；在每次结果到达时显示，不等 300 次全部完成。
- 归属通过同一服务公开的 `https://ipleak.net/json/{ip}` 获取，使用 `country_name`、`region_name`、`isp_name`、`reverse` 等原始字段。每个 IP 每次运行只查询一次，最多并行 4 个，原始 JSON 保留在内存和复制报告中。官网使用同站 HTML 卡片接口显示归属，本工具使用其公开 JSON API，不注入第三方 HTML；可能因上游缓存更新得到不同时间的归属。
- 地区显示国家与省州，命中次数与官网卡片一致。缺失归属保持未知，不用 DB-IP 或 IPPure 补全 DNS 记录。归属失败不抹除真实 IP 和次数。空结果、请求错误、归属错误分别显示，不能当作无泄漏。

## 浏览器路径和取消

检测与归属接口均提供跨域访问授权。开发网页和 WebView2 都由当前浏览器直接请求，使用该浏览器原有的网络和 DNS 路径，无本机采样或结果转发。移除了旧 DNSLeakTest 前端、普通权限后端客户端、HTTP 控制路由和原生消息入口。

仅点击开始才发请求；请求省略 Cookie、认证与 Referrer。不会读写系统代理、DNS、浏览器 DoH、TUN、节点或分流规则。用户停止时取消请求、归属队列和采样间隔；保留已经得到的 IP、命中次数和归属，并明确标记为已停止。迟到响应不会再写入结果。核心采样停止后不再开始排队的网站检测。

应用边界：每个响应最多 256 KiB、每次会话最多 256 个解析器；归属查询最长 10 秒，DNS 探针不另设跳过计时，用户仍可停止。检测请求有错误时保留记录并标记采样不完整，不显示成功结论。

两个独立会话即使来自同一电脑，也可能因时间、浏览器 DNS、轮数和上游调度不同而返回不同列表。对齐的是服务、采样协议和累计规则，不能保证独立采样的 IP 数量或列表完全相同。

## 验证

`npm run test:ipleak-dns` 使用离线模拟核对会话与 300 个域名序号、串行与间隔、命中累计规则、归属映射、失败、停止及迟到响应。`npm test` 使用隔离浏览器和模拟服务验证原页面、卡片、报告、独立操作、桌面 WebView2 消息环境及手机布局；`tests/local-workbench.test.mjs` 验证旧 DNS 控制命令被拒绝。

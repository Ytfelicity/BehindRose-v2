# IPPure 接入（2026-10-18）

按用户要求替换现有 IP 质量体检，不新增检测分区。当前流程不再运行 IPQuality/Docker；旧 AGPL vendor 文件、派生适配器及相关运行/打包入口已从公开源码与构建路径移除。

## 官方来源

- [公开接口说明](https://ippure.com/MyIP-Info-API)：GET https://my.ippure.com/v1/info，返回本次请求出口的归属、风险及类型。接口处于测试阶段，可能变化。
- [官网常见问题](https://ippure.com/faq)：风险系数越高表示风险越高；IPv6 不计算风险系数。
- 官网首页引用的 /assets/chunks/IPDataTable.BZ02Asml.js 保存在 artifacts/ippure-reference/，仅作分档核对，不执行或打包该网页代码。
- 分档采用官网 ColorMap 的上界（包含边界）：15 极度纯净、25 纯净、40 中性、50 轻度风险、70 中度风险、100 极度风险。没有新增自有评分、综合平均或跨库补分。

## 请求路径

当前页面 → 现有受限本机桥 → 普通权限 IpPureRunner → 独立 WebView2 正常打开固定公开接口 → 读取返回 JSON。

实测发现公开接口 HTTP 200 响应没有 Access-Control-Allow-Origin，因此本地页面 fetch 被浏览器拒绝；普通 HTTP 客户端访问又收到了 Cloudflare HTTP 403 验证页。最终使用与正常浏览器打开接口相同的顶层文档导航方式，不关闭 CORS、安全检查，不逆向网站私有 API，不伪造请求签名或分数。

默认使用已识别的本机 HTTP / 混合端口。端口只应用于这次查询的独立浏览器环境参数，连接失败不回退直连。可明确选择“本机默认网络”，沿用系统现有网络行为；该出口可能与浏览器或其它域名的分流不同。以报告实际返回的 IP 为准。

WebView2 使用独立随机临时 profile 和不可见窗口，不访问用户已有浏览器 profile，不接入任何本机消息桥或主机对象，不允许新窗口、下载或敏感权限。顶层导航限制到官方 HTTPS 主机的 /v1/info 路径；遇到验证或非 JSON 内容时报告失败。每次结束关闭 controller，并且只尝试清理自己创建的随机临时 profile。需要已安装 WebView2 Runtime；开发宿主使用和桌面程序相同的固定版本 SDK。

保留原端口识别，仅读取配置及 TCP 监听表，不改 Windows 代理、DNS、TUN、路由、节点或客户端配置。IP 协议由返回地址确定，不以一个双栈域名承诺强制 IPv4 / IPv6。

## 报告与边界

显示原始 fraudScore、isResidential、isBroadcast 和基础地理/ASN 字段；零分、false、null 和缺失各自保留。IPv6 即便意外携带分值也不展示为可用风险系数。缺失字段显示未知，不推测 Cloudflare Bot Score、多库代理/VPN/Tor 因子、解锁或邮件黑名单。

JSON 报告的 Data 保留原始服务字段，Head 仅记录采样时间、地址族和请求方式。只有匹配浏览器同协议出口才补充城市与网络归属。JSON 原文不拼入 HTML；国旗来自本地国家码白名单资源。

单次最长 20 秒、JSON 最多 64 KiB、深度最多 16。无效 IP、错误类型、验证页、拒绝访问和超时均为未取得结果，不当作纯净或零分。停止取消等待并关闭查询，迟到任务不能覆盖新结果。任务与报告保留在本地服务内存，刷新只恢复，不自动重新请求公网接口。

- test:quality：模拟本机与原生桥、准确代理端口、默认网络、验证失败、停止、刷新恢复、IPv6、文本转义和移动布局。没有真实公网或代理请求。

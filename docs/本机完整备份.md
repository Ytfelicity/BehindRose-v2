# 本机完整备份与恢复

在“恢复记录”顶部点击“立即完整备份”。配置未丢失前先保存一份；工具箱修改 Clash 设置前也会自动保存完整配置。备份只在本机进行，无需联网。

## 保存范围

标准 Clash Verge Rev 配置目录内的文件：订阅登记、订阅原文和节点凭据、全局及订阅脚本、覆写、DNS、TUN、分流、节点选择缓存、图标、规则及地理资源。日志、临时文件、崩溃资料和客户端历史备份压缩包不重复保存。源文件按原始字节保存，恢复时不重新生成订阅或更新节点。

程序安装文件、目录外的自定义资源、系统网卡驱动及浏览器注册表策略不在这份 Clash 备份内。浏览器策略仍使用“防护调整记录”撤销。非标准数据目录暂不自动选择；接口不接收自定义读取路径。

备份保存在 `%LOCALAPPDATA%\BehindRose\ClashBackups`，文件扩展名为 `.brclash`。清单和配置内容整体使用随机密钥及 AES-GCM 加密，密钥由当前 Windows 用户的 DPAPI 保护。列表与预览只返回时间、文件数量、大小和范围，不返回节点、链接或配置原文。源码与安装包不内置任何用户备份，Git 和源码检查拒绝纳入此类文件。

## 配置丢失后恢复

1. 在“恢复记录 → 本机完整备份”选择需要的时间点，点击“一键恢复”。原订阅登记或整个配置目录缺失时仍可预览。
2. 核对写入与移除的文件数量。完整恢复会回到备份时的配置，备份后新加的配置文件也会移除；日志和历史备份保留。
3. 从系统托盘退出 Clash，确认范围并执行。无需手动导入每个订阅。程序先保存恢复前快照，再原样还原配置并逐项校验。
4. 重新打开 Clash，检查当前订阅、节点、策略组和 TUN，再检测网络。恢复保留备份当时的开关；如需要开启 TUN，使用“一键配置”。

备份可以反复使用。预览后当前配置或备份文件发生变化会停止执行；中途写入失败会回滚。若回滚未能完成，列表会标记“需要恢复”，并暂停其他写入；优先恢复该记录，恢复前快照始终保留。

## 边界

备份不上传，也不随源码、更新包或安装包分发。加密备份依赖创建它的 Windows 用户密钥，重装系统、丢失用户资料或更换账号可能无法解密。此功能用于本机配置丢失恢复；如计划换机或重装系统，提前另行保管可迁移的私人备份。备份所在磁盘本身损坏也需要其他副本。

单次最多 8192 个文件、未压缩总量 512 MiB、单文件 128 MiB、压缩归档 128 MiB；超限或不安全的链接、重解析点、硬链接和路径会拒绝操作，不截断备份。备份时会重复核对文件清单与摘要；配置正在变化或被占用时，先退出 Clash 后重试。

## 虚拟网卡兼容

一键配置同时开启 Clash 的 TUN 开关、核心 `tun.enable`、自动路由、严格路由和 TCP/UDP 53 接管。沿用 System、GVisor、Mixed 或 Mips 协议栈，以及用户已有的网卡名称、MTU、路由排除和接口排除。有显式 `interface-name` 时保留手动出口，否则启用自动出口识别。不会直接启用其他软件的虚拟网卡。

确认方案中的“虚拟网卡会这样配置”逐项展示实际保留的协议栈、网卡名、MTU、排除项和将开启的路由、DNS 接管。已选择 Mips 时保持 Mips；只有未设置协议栈时补充 Mixed 默认值，无需先去 Clash 改成 Mixed 才能使用工具箱。损坏的配置、未知字段类型或权限错误仍会说明原因并停止，不强行覆盖用户设置。

配置已保存与网卡实际运行分别显示。Clash 服务模式或权限异常仍需在客户端处理，不能把保存成功当作网卡已启动或 DNS 已无泄漏。字段依据见 [Mihomo 官方 TUN 文档](https://wiki.metacubex.one/config/inbound/tun/)。

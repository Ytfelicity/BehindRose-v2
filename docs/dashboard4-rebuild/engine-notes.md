# 界面与接线坐标

这是一份既有应用改造笔记，不是 React Bits Pro 源码逆向结果。

> 本文是历史接线记录。旧 IPQuality / NetQuality 源码、适配器及运行/打包入口已于 2026-10-18 移出公开工程；下文的旧引擎路径与测试说明不代表当前提供的文件或执行流程。当前来源见 [IPPure 接入](../IPPure接入.md) 与 [发布前检查](../开源前检查.md)。

| 模块 | 输入与真实职责 | 本次改动 |
| --- | --- | --- |
| `frontend/src/main.tsx` | hash 路由、同源 iframe 状态观察、检测选项和配置操作锁 | 中性侧栏、紧凑路由、默认关闭的检测抽屉和焦点管理 |
| `Assets/workbench/workbench.js` | 本机状态、配置预览、执行确认、备份恢复 | 不改业务逻辑 |
| `Assets/diagnostics/index.html` | 检测引擎既定 ID、报告按钮、结果区域 | 四项概览、连通性表与右侧来源卡，保留全部 ID |
| `Assets/diagnostics/diagnostics.js` | IP/DNS/RTC 实际采样、取消、结果与原生摘要 | 新增 WebRTC 概览的显示同步，不改探针逻辑 |
| `frontend/src/connectivity-ui.tsx` | 现有 MyIP 目标及请求调度、自定义列表 | 结果布局改为四列表格，保持原逻辑和状态语义 |

公开参考只提供视觉层观察：深色卡片、清楚的指标层级、表格和状态列表。没有解析其脚本、source map、隐藏应用状态或受限注册表。所有产品数据仍属于当前工具的真实状态。

关键契约：单项检测按钮 `dns-run` / `rtc-run`；概览 `dns-overview-count` / `rtc-overview-count`；整组开始/停止/复制/清空 ID 不变；四个选项与本机操作时的 `iframe.inert` 保持。WebRTC 概览数是成功返回地址的来源数，不表示网络安全结论。

## 2026-10-10 用户实测修复

- 真实页面中，网站组运行时核心检测入口仍可点击、顶部停止禁用。`connectivity-ui.tsx` 现在同步发布任务开始与结束（包含停止原因），提供当前任务锁和完成站数；`diagnostics.js` 合并锁定状态，强制事件也不能绕过互斥。独立网站检测更新顶部范围、进度、耗时、报告和八项原生摘要；原有核心检测后再检测网站的两阶段顺序保持。
- 网站任务停止由当前控制器的 `finally` 发布，过期任务不能覆盖新任务。已有 IP / DNS / WebRTC 结果与各自采样时间在单独网站检测中保留。两项完整模拟回归验证快速连续点击、取消排队与迟到结果隔离、150 次 favicon 请求和十轮最低值。
- 切页期间网络 iframe 的节点可能已卸载；观察网站锁之前确认开始按钮存在且仍连接文档，初始化时同步读取禁用状态。
- 默认 IPv4 质量体检真实运行停在第 1/21 步，容器未从 ipify 取得有效出口、报告为空。界面仅针对已知的这一条错误明确 Docker / 指定代理的检测环境，其他原始错误保留；不暗示本机浏览器断网，不改系统代理或网络。
- 随后质量体检完整实测成功，黑名单查询 420 项（382 未列入、38 失败 / 未知）。媒体阶段原先直到七个服务全部结束才发布结果，中途停止会丢掉已完成项目。`vendor/IPQuality/adapter.sh` 现逐项发布，最终结构保持；固定镜像断网测试执行真实循环，验证七项递增报告、未知字段与中途退出保留。DevHost 运行 adapter 已与源码同步，无需重启服务。
- 最终 TypeScript、完整控制台流程与网站 UI 回归均通过。本机代理注册表、WinHTTP、DNS 地址与持久 IPv4/IPv6 路由的前后快照 SHA-256 相同；没有执行应用、还原或打开 Clash。
- 真实结果页选中标签原本为 `rgb(11,11,11)` 字体配 `rgb(35,35,35)` 背景：全局按钮的重要背景覆盖了局部选中背景。质量标签规则现限定 `#ip-quality` 并明确两种颜色的级联优先级；实际核验为深色字体配 `rgb(237,237,237)` 浅色背景。窄屏在自适应画布完成缩放后无页面横向溢出，宽表在自身容器内滚动。

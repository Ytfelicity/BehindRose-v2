浏览器网络采样期间，网站检测按钮保持可用。手动开始网站检测会先取消并等待浏览器采样结束，保留已取得结果，再启动网站请求；组合采样仍按原顺序执行。取消切换不启动网站请求，连续点击不重复开始。前端类型检查、生产构建、网站交互回归、完整桌面及手机模拟回归通过，包含仍在运行的 WebRTC 探针停止及等待用例。发布构建及 C# 59 项离线测试通过。

最终 Velopack 便携包独立解压后，在 WebView2 中运行实际网站检测：Google、YouTube、GitHub、Cloudflare、Claude、ChatGPT、WeChat 七站均收到 HTTP 200；该次选择每站一次，沿用 3.6 秒超时。19 个本地图标、5 份字体、2 份国家数据库及各分组图片解码也通过，非检测阶段的外部界面资源请求为 0。

排查期间保留了多次真实请求超时的记录。单文件与目录发布、安装标记及浏览器测试目录的对照结果不一致，不能据此认定单文件或更新框架造成 DNS 故障；已撤回该归因。没有改动系统代理、DNS、TUN、路由或检测超时来获得通过结果。一次成功只证明当次网络路径可用。

本机原有便携安装通过已校验的本地完整更新包从 preview.3 替换为 preview.4 并自动重启。正常模式的本机 API 返回新版及就绪状态，运行 DLL 与已验收便携包哈希一致，偏好文件哈希保持不变；桌面快捷方式仍指向同一安装目录。此项验证使用缓存包应用更新，不冒充原先尚未验收的弹窗拒绝、确认及 GitHub 下载全过程。Windows 界面工具仍报 FrameArrived timed out；可读取正式窗口控件，但不能据此宣称截图或输入验收通过。

正式窗口随后完成默认每站十次的真实检测：七站均为 10/10 成功，共 70/70 次采样。preview.4 的六个 GitHub 附件逐一核对 SHA-256、大小和上传状态后发布，匿名读取发布元数据及更新索引成功。

最后检查发现更新适配器的 15 秒等待过短：框架日志在 23 秒和 43 秒后正常判断版本，但调用方已经报超时。preview.5 将后台等待调整为 90 秒，保留取消和用户确认。显式真实 GitHub 只读测试通过，同一适配器在 48 秒后正常返回；没有下载或安装包。该检查不属于默认离线套件。

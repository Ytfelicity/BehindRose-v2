# 沿用本机代理的 DNS 增量防护

默认一键配置保留本机配置，增量修复 DNS。内部 `SingMix` 枚举、脚本登记编号和 `singMix` 健康字段暂保留，以兼容原 API 和恢复记录；当前编译资源使用 `dns-protection.js`。

## 当前方案

- 只读检查 Clash 已生成的运行配置，从现有 MATCH 找到默认代理出口；不创建“全部／AI”等策略组。找不到有效出口时明确停止。
- 保留节点、订阅来源、代理组、原规则顺序、规则集合、TUN 协议栈与缓存设置。只补充缺失的防护例外。
- 包装当前订阅的原脚本，先执行原脚本，再执行 DNS 增量修复；原脚本文件不改写。脚本绑定和新文件照常进入受保护备份与恢复。
- 默认 DoH 显式绑定本机现有代理组。browserleaks.com、browserleaks.org、ipleak.net、ip.skk.moe、dnsleaktest.com、whoer.net 同时设置连接规则与 DNS 策略；已有专用代理出口继续保留。
- 保留局域网自定义解析，修正已知国外分类的旧国内解析策略，清理 fallback；节点独立引导解析避免循环。网易／战网的 11 条直连规则只在缺失时补充；已有广告过滤组保留。
- 客户端默认与当前订阅的 DNS 覆写关闭，避免客户端在合成配置末尾覆盖增量结果；其他订阅单独开关保持原值。
- 桌面 WebView 检测读取正在监听的本机 Clash HTTP／混合端口，绑定该端口；多个冲突端口或未找到时显示未识别，不猜 7890。端口更改后需重启工具箱。浏览器开发页明确标注跟随当前浏览器网络。

## 预览与恢复

预览读取运行配置、原脚本和订阅登记，将它们纳入并发指纹，但只允许写入登记文件、自有脚本、TUN 与浏览器目标设置。只读来源不能成为恢复记录的写入目标。原脚本变化或切换订阅会使预览失效。旧版完整模板已经覆盖分流的情况，先在恢复记录还原，增量修复不会伪造已丢失的原策略组。

已保存、已识别代理端口、Mihomo 配置可加载和实际 DNS 无泄漏是不同证据。界面保留“待检测”状态，不将文件存在视为网络验收通过。

## 私人配置边界

源码和发行包仅提供通用防护逻辑与虚构测试数据，不内置作者或用户的节点、服务器地址、订阅链接、认证凭据和整份 Clash 配置。每位用户需先导入自己的订阅；程序运行时在本机识别现有配置。

修改 Clash 前自动建立本机加密完整备份，“恢复记录”也可手动备份和还原整份配置；订阅和整个配置目录缺失时仍可使用。单次防护调整记录保留独立的撤销范围。[完整备份说明](本机完整备份.md)。真实配置快照、备份和网络采样记录均属于私人资料，应放在项目目录外，不纳入源码或发行包。

## 验证

验证包括 C# 核心测试、增量 JS 保留/幂等/原脚本调用测试，以及配置页和本地 API 的预览/应用/恢复演示。实际环境还需检查原有节点、策略组、规则、TUN 是否保留，使用对应 Mihomo 核心校验生成配置，并经本机代理实测 DNS 出口。私人实测资料不随源码提供。旧安装包不会随源码编译自动更新。

# 程序更新

项目继续采用 BehindRose Noncommercial License 1.0，禁止商业用途；更新功能不改变项目和第三方代码的许可。

## 用户体验

支持更新的正式分发包启动后后台检查 GitHub Releases。有新版时显示版本和更新说明，用户点“是”后才下载；点“否”保留当前版本，下次启动再检查。设置页提供“检查更新”。下载有进度和取消按钮，完成并校验后关闭当前程序、应用更新并重新打开。

EXE 默认显示与开发模式相同的完整网页工作台，不再默认显示旧的 WPF 功能页；“帮助与关于”中提供版本和更新状态。旧界面只在显式传入 --legacy-ui 时用于兼容排查。工作台资源和本机服务随包提供，用户无需安装 Node.js。

preview.4 起使用完整目录的自包含发布：本机对照实测中，单文件发布的 WebView2 系统域名解析卡住，目录发布可完成真实网站请求。安装包和便携包仍自带所需运行时；保留 current 目录中的全部文件，不要只复制其中的 EXE。

检查失败不阻止启动；取消或下载/校验失败不启动安装。配置写入与恢复期间暂缓提示，下载期间阻止新的配置操作。更新前停止应用内网络采样。更新只更新程序文件，偏好设置仍在 LocalAppData，配置备份仍在 ProgramData 的独立目录。

自动更新依赖 Velopack 1.2.161（MIT）。使用 HTTPS 访问发布时固定的公开 GitHub 仓库，不内置 GitHub Token；GitHub 会收到普通更新请求及来源 IP。预览版本同时考虑预发布，稳定版本只考虑正式发布；不自动降级。已下载的更新也不在下次启动时未经确认自动应用。

源码、开发/演示模式及旧版普通便携包不具备完整更新安装布局。首次分发时应使用下面生成的 Velopack 安装包或便携包，保留其全部文件。旧版本无法凭空获得更新功能，需要先安装一次支持更新的新包。

## 首次绑定仓库

公开仓库为 [Ytfelicity/BehindRose-v2](https://github.com/Ytfelicity/BehindRose-v2)，源码默认更新地址已绑定该仓库。在项目根目录运行（按实际发版修改版本和说明文件）：

```powershell
pwsh -File scripts/build-updates.ps1 -Publish `
  -Repository 'https://github.com/Ytfelicity/BehindRose-v2' `
  -Version '2.0.0-preview.1' `
  -ReleaseNotes 'docs/releases/2.0.0-preview.1.md'
```

需要 Windows x64、.NET 10 SDK、Node.js。可用 `-Dotnet 'C:/SDK/dotnet.exe'` 指定 SDK；首次执行会还原项目内固定版本的 vpk 打包工具。ReleaseNotes 是已有 Markdown 文件，可省略。首次构建先在 frontend 执行 npm ci；发布脚本自动运行前端类型检查和生产构建，再将资源嵌入 EXE。脚本生成本地发布文件，不创建 GitHub 仓库，不上传或发布。

绑定地址通过 `UpdateRepository` 编译元数据写入程序；程序版本来自同一 ReleaseVersion。更换作者或仓库地址后，旧客户端仍查询旧仓库，需要在旧仓库提供一次迁移更新。

## 每次发版

1. 用严格递增的语义版本（例如 preview.1 → preview.2 → 2.0.0），运行相同打包命令。
2. 在绑定仓库创建对应版本的 GitHub Release；预览版勾选 Pre-release，发布后不要保持 Draft。
3. 将 artifacts/updates 的 feed JSON、索引引用的全部 nupkg、安装 EXE、便携 ZIP 等文件一同上传到该 Release。不要只上传 EXE，客户端还需要更新索引和包。保留安装包/便携包的整个布局；原 scripts/build.ps1 的普通 ZIP 不能替代支持更新的便携包。
4. 用上一个版本的支持更新的分发包验收：启动弹窗、稍后更新、立即更新、取消、网络失败、更新后版本、偏好与备份保留。完成后再对外宣布更新可用。

本项目固定 packId 为 BehindRose.NetworkAssistant、channel 为 win，不在发版间随意修改。脚本不会上传，GitHub 登录凭据也不进入客户端。

## 当前验证范围

已提供更新流程的离线回归测试，覆盖明确同意、拒绝、配置操作互斥、取消、下载失败、重复检查、未打包运行和仓库地址约束。框架负责语义版本比较、包校验、替换和重启。

真实 GitHub Releases 的跨版本下载、替换和重启应在独立目录验收，结果见 [公开前检查](开源前检查.md)。可用 `BehindRose.exe --update-test` 进入更新测试：配置和备份使用内存演示状态，不写真实配置、偏好文件或备份目录；更新会访问真实仓库。该参数会随更新重启保留。普通 `--demo` 不检查更新，浏览器网络采样仍由用户手动启动。

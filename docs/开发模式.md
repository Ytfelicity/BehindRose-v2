# 开发体验入口

当前阶段以源码运行和快速体验为主。除非明确要求发布，不执行 `publish`，不生成新的 ZIP 或安装包；旧发布包仅作为历史版本保留。

## 完整浏览器工作台

双击项目根目录的 **启动开发模式.cmd**，进入 <http://127.0.0.1:4317/>。旧的 **启动检测页面.cmd** 也进入同一工作台。

- **本机体检**：识别 Clash 版本与运行状态，读取 TUN / DNS 接管和浏览器 DNS 策略。只读，不自动联网。
- **网络检测**：公网 IP、DNS 解析出口和 WebRTC；DNS 按官网原始列表显示 IP、Hostname、ISP、Country。点击开始后才连接检测服务。
- **修复配置**：选择 TUN、Chrome、Edge、Firefox 或默认 DNS；先展示实际变更，再确认执行。修改前自动备份，失败时回滚。
- **备份与恢复**：读取当前用户的 v2 备份，预览恢复范围，发现后续改动时停止恢复。
- **设置与关于**：深色 / 浅色 / 跟随系统、复制不含配置原文的本机体检摘要。

Node 服务直接读取 `src/BehindRose.Desktop/Assets/workbench` 和 `Assets/diagnostics`。保存 HTML / CSS / JS / SVG 后自动刷新；进行中的网络采样会结束，需要再次点击开始。

启动时构建 `BehindRose.DevHost` 的 Debug 版本。修改 C# 或 `scripts/*.mjs` 后，在控制台按 Ctrl+C 并重新启动；刷新浏览器不重新编译 C#。运行依赖 Node.js 和 .NET 10 SDK，优先使用 `../tools/dotnet10/dotnet.exe`，否则使用 PATH 中的 `dotnet`。

配置操作沿用 Windows 管理员授权与受保护备份。邀请码与在线激活已移除，支持作者完全自愿。预览有效期为 10 分钟，执行后旧预览失效。原始配置和备份内容留在本机服务内；HTTP 接口校验 Host、Origin、会话令牌及命令白名单，不接受任意文件路径或脚本。开发服务不自动更新自身；正式分发包的更新见 [程序更新](程序更新.md)。

操作期间可切换页面，网络检测暂时不能开始。刷新页面会重新读取本机服务中的进行中操作。关闭控制台不会主动终止已启动的配置工作进程；重启服务后请通过备份页核对未完成的操作。

## 原桌面流程

执行 `pwsh -File scripts/dev.ps1 -Mode Desktop`。

入口会找到工作目录中已有的 .NET 10 SDK，使用 Debug 配置运行项目，并启用源码监听。标题栏显示“开发模式”。控制台保持打开；停止开发会话可在控制台按 Ctrl+C。

- 检测页面的 HTML、CSS、JavaScript 从 `src/BehindRose.Desktop/Assets/diagnostics` 直接读取，保存后重新加载页面。页面刷新会结束上一轮采样，需要再次点击开始。
- C# 由 `dotnet watch` 处理支持的热更新；需要重启的修改由监听工具重新构建。WPF XAML 的即时更新能力有限，遇到界面没更新时，在控制台按 Ctrl+R 重启应用。
- 此入口仍具备真实本地体检、配置和恢复能力，配置操作依旧需要明确确认和 UAC；它不是静态演示。
- 想只体验示例修复流程，可以执行 `pwsh -File scripts/dev.ps1 -Demo`。演示模式不会修改真实配置或进行外网检测。

开发运行仍会生成正常的 `bin/Debug` 中间产物，这是 C# 程序运行所需的编译输出，不需要手工找 EXE、打包或解压。

## 网络检测范围

双击 **启动检测页面.cmd**，或在启动服务后打开：

<http://127.0.0.1:4317/>

页面直接读取同一份 HTML、CSS 和 JavaScript，保存后自动刷新。只有本地开发服务，未部署公网，不增加系统代理设置，不转发或代测外网请求。

浏览器与 WebView2 的代理、扩展和权限环境可能不同，因此网页里成功不能替代桌面内检测的验证。本机体检与修复功能已经接入浏览器工作台。

浏览器可以使用开发者工具查看失败请求和错误。检测仍然需要点击“开始”，不会因保存文件或刷新自动联网。自动刷新连接只访问本机。

## 常用命令

```powershell
# 完整浏览器工作台
pwsh -File scripts/dev.ps1

# 只运行一次，不监听 C# 改动
pwsh -File scripts/dev.ps1 -Mode Desktop -NoWatch

# 兼容旧的检测页启动方式，也进入完整工作台
pwsh -File scripts/dev.ps1 -Mode Diagnostics

# 只启动本地网页服务，不自动打开浏览器
node scripts/dev-server.mjs

# 构建 Debug 后，验证内存中的修复恢复流程及本地 HTTP 接口边界
node tests/local-workbench.test.mjs
```

DNS 探针请求参数冲突及服务错误响应的误报已修复，开发页已实际取得解析器结果；服务仍可能间歇性超时。详见 [排查与验证记录](2026-09-22-开发模式与DNS修复.md)。旧发布包不包含本次修改，请使用开发入口。
